# Experiment protocol

Baseline A is the pinned pretrained model with a compact tool description; baseline B adds schema/examples; experiment C is the same revision with a LoRA adapter if feasible. All variants use the same parser, executor, policies, and locked test split. Select prompts/hyperparameters with train/validation only. Record model/adapter revision, seed, prompt version, dataset/checksum, parameters, software, hardware, timestamp, duration, numerator/denominator, and categorized failures.

`experiments/evaluation/run_model_benchmark.py` runs one frozen configuration at a time and saves action-type, exact tool, exact arguments, latency, environment and dataset checksum fields. Example: `python experiments/evaluation/run_model_benchmark.py --variant baseline_a --split validation`. Run baseline B in a separate process. For an adapter, use `--variant lora_c --adapter <saved-adapter-dir> --qlora --split validation`; QLoRA loading requires CUDA and `backend[train]`. `--limit N` is for a smoke only and must not be reported as a full benchmark. The script defaults to validation; use the locked test split only after prompt/configuration choices are frozen. It measures action selection only and does not execute tools.

The fixture runner exercises validation with simulated rules. Never treat fixture behavior as model evidence. A/B/C validation and locked-test action-selection runs are saved. All scored 0/48 exact validation actions; on locked test, exact actions were A 23/60, B 24/60 and C 24/60. C had a higher schema-valid rate, but did not beat B on exact action match. C used NF4 inference while A/B used FP16, so latency comparisons do not isolate LoRA. The family-separated split and small synthetic dataset limit generalization claims. No tool execution or end-to-end task success is measured.
